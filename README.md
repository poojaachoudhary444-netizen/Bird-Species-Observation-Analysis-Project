# 🦅 Bird Species Observation Analysis

Analyzes bird species distribution and diversity across **Forest** and **Grassland**
ecosystems using temporal, spatial, species, environmental, and conservation lenses —
per the project brief.

## Project structure

```
bird_project/
├── data/
│   ├── Bird_Monitoring_Data_FOREST.xlsx      # raw, multi-sheet (one sheet per admin unit)
│   ├── Bird_Monitoring_Data_GRASSLAND.xlsx   # raw, multi-sheet (one sheet per admin unit)
│   └── bird_data_cleaned.csv                 # generated by app.py
├── db/
│   └── bird_observations.db                  # generated by app.py (SQLite)
├── generate_sample_data.py                   # builds a SYNTHETIC demo dataset
├── app.py                                     # ETL: load → clean → engineer → save (CSV + SQLite)
├── Bird_Species_EDA.ipynb                     # full data cleaning + exploratory analysis notebook
├── dashboard.py                               # Streamlit interactive dashboard
├── requirements.txt
└── README.md
```

## ⚠️ About the data

This project ships with a **synthetic sample dataset** (see `generate_sample_data.py`)
so the notebook, `app.py`, and the dashboard all run out of the box. It mirrors the
exact schema from the project brief (29 columns, 11 admin units — ANTI, CATO, CHOH,
GWMP, HAFE, MANA, MONO, NACE, PRWI, ROCR, WOTR — split across Forest and Grassland
workbooks) but the values themselves are randomly generated and **not real
observations**.

### To use the real dataset
Replace these two files with the real workbooks (same sheet-per-admin-unit layout),
keeping the file names, then re-run `python app.py`:

```
data/Bird_Monitoring_Data_FOREST.xlsx
data/Bird_Monitoring_Data_GRASSLAND.xlsx
```

No other code changes are needed as long as column names match the brief
(`Admin_Unit_Code`, `Location_Type`, `Common_Name`, `Scientific_Name`, `Temperature`,
`PIF_Watchlist_Status`, etc.).

## How to run

1. **Install dependencies**
   ```bash
   pip install -r requirements.txt
   ```

2. **(Optional) Generate the sample dataset** — skip this once you have real data
   ```bash
   python generate_sample_data.py
   ```

3. **Run the ETL pipeline** — cleans data and builds the SQLite DB + CSV
   ```bash
   python app.py
   ```

4. **Explore in Jupyter** (cleaning steps, EDA, charts, findings)
   ```bash
   jupyter notebook Bird_Species_EDA.ipynb
   ```

5. **Launch the interactive dashboard**
   ```bash
   streamlit run dashboard.py
   ```
   Then open the URL Streamlit prints (usually http://localhost:8501).

## What the dashboard covers

| Tab | Content |
|---|---|
| Overview | KPI cards, habitat split, top species, observations by admin unit |
| Temporal Trends | Year-over-year, seasonal patterns, year×month heatmap, time-of-day activity |
| Spatial / Habitat | Biodiversity hotspots by admin unit and plot, habitat comparison |
| Species Analysis | Sex ratio, ID methods, species-by-habitat preference, per-species drill-down |
| Environment | Temperature/humidity vs. counts, sky condition, disturbance effects |
| Distance & Behavior | Distance bands, flyover rate, closest/farthest-observed species |
| Observers | Observations & species diversity per observer, effect of repeat visits |
| Conservation | PIF Watchlist & Regional Stewardship species, hotspots for at-risk birds |

All tabs respond to the sidebar filters (habitat, admin unit, year, species,
observer, watchlist status).

## Notes

- `app.py` is written as an importable module — the notebook does
  `import app` and reuses `app.load_raw_data()` / `app.clean_data()` /
  `app.save_outputs()` so the notebook and the dashboard's database never drift
  out of sync.
- Missing numeric values (temperature, humidity) are imputed with the
  species-level median; rows without a species ID are dropped since every
  downstream analysis depends on species identity.
